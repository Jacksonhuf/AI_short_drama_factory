> 本文是持续维护的产品规划。当前已经上线的能力以[产品概览与生产链路](/docs/architecture/product-overview/)为准；本 PRD 中的“目标态”和“待补齐”不代表已经实现。

## 1. 产品问题与愿景

AI 短剧生产的难点不只是单次调用模型，而是把剧本、资产、镜头、提示词和生成结果组织成可复用、可确认、可追溯的生产资料。传统的“输入提示词 → 得到媒体”模式会造成资产漂移、镜头上下文丢失和长任务不可控。

元风 的目标是成为 AI 短剧的生产操作系统：让创作者从章节剧本开始，在每一个会影响后续生成质量的节点完成必要确认，并以任务系统追踪异步生成的结果。

### 成功定义

一个最小可用的项目闭环应满足：

1. 用户能创建项目和章节，并录入或修订章节剧本。
2. 用户能得到分镜和资产/对白候选，并在分镜编辑页完成确认。
3. 用户能在工作室明确知道每个镜头是否具备视频生成条件，以及缺失什么。
4. 用户能发起图像或视频任务、观察状态、失败后定位并再次处理。
5. 生成结果能回到镜头和素材上下文，可进入轻量时间线。

## 2. 用户与使用场景

### 目标使用者

| 使用者 | 核心诉求 | 典型动作 |
| --- | --- | --- |
| 独立创作者 | 快速将故事转成可生成镜头，减少重复整理。 | 写章节、确认资产、生成关键帧和视频。 |
| 制片/导演 | 控制视觉一致性与镜头质量。 | 审核候选、维护角色/场景、检查视频准备度。 |
| 制作运营 | 批量推进任务并定位失败。 | 查看任务、重试失败项、整理媒体与时间线。 |

当前不把这些角色实现为系统权限。认证、协作、审核流和多租户是后续产品能力，不能假设已具备。

### 关键场景

1. 新项目从一段章节剧本拆分出可编辑的镜头。
2. 提取结果有误时，创作者能在生成前关联既有资产、忽略候选或补充信息。
3. 制片需要在批量生成前发现缺关键帧、缺模型或存在运行中任务的镜头。
4. 长时生成失败后，用户能从任务中心回到相应项目、章节或镜头继续处理。

## 3. 产品原则

1. **人机协作而非黑盒自动化**：提取和生成可自动执行，但关键生产信息必须可确认、修正和追溯。
2. **一致性优先**：角色、场景、道具和服装应沉淀为可复用资产，而非每个镜头重新描述。
3. **状态语义单一**：信息确认、视频准备度和运行任务状态不能混为一个“进度”标签。
4. **页面职责明确**：编辑页负责准备，工作室负责生成，任务中心只承担轻量追踪。
5. **先闭环后扩展**：先保证从剧本到可追踪生成结果的流程成立，再增加协作、剪辑和高级自动化。

## 4. 范围

### 本阶段范围

| 域 | 必须具备的产品能力 | 当前基线 |
| --- | --- | --- |
| 项目与章节 | 项目创建、章节管理、剧本录入和阶段入口。 | 已具备主流程。 |
| 分镜准备 | 分镜拆分、候选提取、人工确认和 `ready` 推进。 | 已具备主流程。 |
| 资产一致性 | 全局资产库、项目/镜头关联、图片生成与复用。 | 已具备主流程。 |
| 生成工作室 | 视频准备度、关键帧、提示词预览、单/批量生成。 | 已具备主流程。 |
| 任务系统 | 异步执行、进度、取消、结果回流和回跳。 | 已具备主流程。 |
| 媒体与剪辑 | 文件归档、基础时间线和轻量编辑入口。 | 基础能力，持续完善。 |

### 明确非目标

- 在当前阶段复刻专业非线性视频编辑器。
- 用单一“生成中”字段取代各类状态。
- 让任务中心承载提示词、图文映射等业务详情。
- 将未验证的 Agent 管理 UI 视为生产工作流的必经入口。
- 在没有权限、审计和数据隔离设计前承诺多租户协作。

## 5. 功能需求

### 5.1 项目与章节

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| PRD-P01 | 用户可创建项目并配置题材、视觉形式、默认视频比例和统一风格。 | 新项目可出现在项目列表，配置能被章节/镜头生成流程读取。 |
| PRD-P02 | 用户可管理章节剧本，并获得下一步生产动作。 | 项目工作台能按章节状态引导编辑原文、提取分镜、准备或进入工作室。 |
| PRD-P03 | 用户可从项目进入章节、镜头和生成工作室，不丢失上下文。 | 页面跳转携带项目、章节和镜头标识，面包屑与返回路径可用。 |

### 5.2 剧本理解与分镜准备

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| PRD-S01 | 用户可对章节启动拆分和提取任务。 | 任务在任务中心可见，完成后镜头与候选可刷新。 |
| PRD-S02 | 用户可确认、忽略或关联资产与对白候选。 | 每个候选的决策可保存，镜头状态按统一规则更新。 |
| PRD-S03 | 用户可编辑镜头基础信息、镜头语言和动作拍点。 | 保存后准备聚合状态与后续生成上下文一致。 |
| PRD-S04 | 用户可跳过不需要的提取，但该决定应可见。 | `skip_extraction` 影响 ready 判定并在界面中可识别。 |
| PRD-S05 | 准备完成后应明确引导用户前往分镜工作室。 | 编辑页不把关键帧和视频生成作为主操作；完成提示提供工作室入口。 |

### 5.3 资产与一致性

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| PRD-A01 | 用户可管理演员、角色、场景、道具、服装及其图片。 | 资产可创建、编辑、检索和在项目/镜头中关联。 |
| PRD-A02 | 角色应能组合演员、服装和道具，以表达镜头级一致性。 | 分镜关联角色后，生成上下文能使用角色相关资产。 |
| PRD-A03 | 用户可在新增前检查和复用同名资产。 | 候选确认与资产创建路径能提示既有可复用实体。 |

### 5.4 生成与任务

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| PRD-G01 | 工作室应展示视频准备度及缺失项。 | 用户能区分“信息已确认”与“视频可生成”，缺失项可定位到修复入口。 |
| PRD-G02 | 用户可维护关键帧、参考图、视频比例、时长和提示词。 | 提交前的预览与最终 provider payload 使用同一份有效草稿。 |
| PRD-G03 | 用户可发起单镜头和批量图片/视频生成。 | 每次操作生成可追踪任务，并避免与进行中视频任务冲突。 |
| PRD-G04 | 用户可追踪、取消和回跳任务。 | 状态、进度、结果与失败信息可见；取消为 best-effort，界面不承诺供应商强终止。 |

### 5.5 后续补齐需求

| 编号 | 需求 | 优先级 | 结果口径 |
| --- | --- | --- | --- |
| PRD-F01 | 统一所有前端 API 调用到 OpenAPI 生成客户端。 | P0 | 移除 Agent、文件、剪辑等主页面的手写 API 双轨。 |
| PRD-F02 | 建立认证、项目成员与最小权限模型。 | P1 | 用户、项目成员和权限检查进入后端契约与前端路由。 |
| PRD-F03 | 统一错误恢复体验。 | P1 | 页面级错误有原因、重试和回退操作，任务失败保留诊断入口。 |
| PRD-F04 | 完善轻量时间线与导出前检查。 | P2 | 生成视频可被编排、预览并检查缺失素材，不扩展为专业剪辑器。 |
| PRD-F05 | 使 Agent 管理成为真实可配置能力，或移除其伪入口。 | P2 | UI、API、运行时配置和审计口径一致。 |

## 6. 指标与验收

没有基线数据前，不设伪精确数值；先建立以下可测指标：

| 维度 | 指标定义 | 观测节点 |
| --- | --- | --- |
| 闭环完成率 | 创建章节后，至少一个镜头完成视频生成的项目占比。 | 项目/章节生命周期。 |
| 准备通过率 | 进入工作室的镜头中，通过 video-readiness 的占比。 | 视频准备度检查。 |
| 返工率 | `ready` 后因资产/对白确认问题回退的镜头比例。 | 镜头状态与候选变更。 |
| 任务可靠性 | 任务首次完成率、失败后恢复率和平均排队/执行时长。 | GenerationTask。 |
| 一致性复用 | 新生成镜头关联既有资产的比例。 | 项目/镜头资产关联。 |

指标采集、权限和埋点尚未实现，属于配套交付，不得把前端展示的模拟统计当作真实数据。

## 7. 依赖、风险与里程碑

### 外部依赖

- MySQL、Redis、Celery Worker、S3 兼容对象存储。
- 可配置的文本、图像与视频供应商。
- 稳定的 OpenAPI 契约和生成客户端同步流程。

### 主要风险

| 风险 | 应对原则 |
| --- | --- |
| 模型输出不稳定 | 保留人工确认节点，复用资产与提示词模板。 |
| 长任务失败或延迟 | 以 GenerationTask 为真相，提供可见状态、取消和回跳。 |
| 状态含义混乱 | 禁止用 `shot.status` 表示运行时生成；测试和文档同步维护。 |
| 页面职责膨胀 | 每次新增交互先判断属于准备、生成还是通用任务追踪。 |
| 云端部署误配 | 静态前端与常驻 API/Worker/存储分开部署并显式配置 CORS。 |

### 推进顺序

1. 结构与契约治理：API 双轨收敛、数据和状态语义测试。
2. 核心流程体验：提取确认、准备度诊断和错误恢复。
3. 生成质量与可观测性：提示词、任务指标和供应商能力约束。
4. 轻量后期与协作：时间线衔接、导出检查、认证与成员模型。
