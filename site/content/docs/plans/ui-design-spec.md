> 本文定义目标 UI 规范与待改造项。当前页面实现与职责边界见[产品概览](/docs/architecture/product-overview/)及各架构文档。

## 1. 设计目标

元风 是高信息密度的创作生产工作台，不是面向访客的营销站。界面应帮助用户持续回答四个问题：

1. 我现在处于哪一个生产阶段？
2. 下一步该做什么？
3. 这个镜头为什么还不能生成？
4. 正在执行的任务、失败结果和生成素材在哪里？

设计优先级为：**生产清晰度 → 状态可解释性 → 操作效率 → 视觉表现**。

## 2. 设计原则

| 原则 | 规则 |
| --- | --- |
| 阶段明确 | 在项目、章节、镜头三个层级显式展示当前位置和下一动作。 |
| 状态分离 | 信息确认、视频准备度、运行任务必须使用不同标签、文案和位置。 |
| 上下文不丢失 | 从任务、诊断、资产跳转时，保留项目/章节/镜头上下文和返回路径。 |
| 渐进披露 | 默认展示执行下一步所需信息；提示词、原始响应和调试信息进入按需面板。 |
| 可恢复 | 错误应说明原因、影响范围与下一步，而不是只显示 toast。 |
| 桌面优先 | 分镜编辑和工作室首先服务 1024px 以上桌面；窄屏提供可用的单栏降级。 |

## 3. 目标信息架构

```text
项目列表
  └─ 项目工作台
       ├─ 概览 / 章节
       ├─ 项目资产与文件
       ├─ 分镜列表
       │    └─ 分镜编辑页（准备）
       ├─ 分镜工作室（生成）
       └─ 轻量时间线

全局：资产库、提示词模板、模型设置、任务中心、设置
```

### 导航规则

| 位置 | 应提供 | 不应提供 |
| --- | --- | --- |
| 主侧栏 | 项目、资产、提示词、模型、设置等稳定入口。 | 仅开发或 mock 状态的产品入口。 |
| 项目工作台 | 当前项目的章节、资产、文件和下一步。 | 需要离开项目上下文才能理解的全局操作。 |
| 分镜编辑页 | 当前章节、镜头队列、候选确认和准备进度。 | 视频生成主按钮。 |
| 分镜工作室 | 选中镜头、准备度、关键帧、视频参数和生成结果。 | 大规模提取候选确认表单。 |
| 任务中心 | 通用状态、进度、取消、回跳。 | 大段提示词、媒体映射或供应商调试详情。 |

`/files`、`/agents` 等已有路由应在信息架构评审中决定“提供受控入口”或“下线”，不能长期处于可访问但不可发现的状态。

## 4. 设计系统

### 4.1 基础令牌

当前界面存在 `#1677ff`、`#3b82f6`、`#6366f1` 等多套主色。目标是收敛为一个以靛蓝为主、绿色表达成功/可执行的工作台系统：

| Token | 值 | 使用 |
| --- | --- | --- |
| `color.primary` | `#6366F1` | 主要操作、选中导航、焦点环。 |
| `color.primary-hover` | `#4F46E5` | 主操作 hover/active。 |
| `color.success` | `#10B981` | 完成、可生成、成功任务。 |
| `color.warning` | `#F59E0B` | 待确认、需注意、部分缺失。 |
| `color.error` | `#DC2626` | 失败、阻断、不可恢复错误。 |
| `color.surface` | `#FFFFFF` | 卡片、面板与表单背景。 |
| `color.canvas` | `#F5F3FF` | 应用背景与弱分区。 |
| `color.text` | `#1E1B4B` | 主要文字。 |
| `color.text-muted` | `#475569` | 次级文字，浅色背景下保持可读。 |

- 字体建议使用 `Plus Jakarta Sans`；加载必须使用 `font-display: swap`，并保留系统字体回退。
- 圆角采用 6px（输入/按钮）和 12px（卡片/工作区）的两级体系。
- 动画限定在 150–300ms 的透明度、颜色和阴影变化；遵守 `prefers-reduced-motion`。
- 图标统一使用 Ant Design Icons 或同一套 SVG 图标，不使用 emoji 作为交互图标。

### 4.2 组件状态

| 组件 | 必须状态 |
| --- | --- |
| Button | default、hover、active、disabled、loading、focus-visible。 |
| Input / Select | label、help、error、disabled、focus-visible。 |
| Card / List item | default、hover、selected、loading、empty、error。 |
| Status tag | 文本 + 图标/形状，不能只靠颜色区分。 |
| Async action | 进行中反馈、成功确认、失败原因和重试/回退操作。 |

所有可点击卡片和图标按钮必须有 `cursor: pointer`、键盘 focus 样式及不改变布局的 hover 反馈。

## 5. 状态呈现模型

### 5.1 三类状态的视觉语义

| 状态 | 推荐文案 | 位置 | 视觉语义 |
| --- | --- | --- | --- |
| 信息确认 | 待确认 / 已确认 | 分镜列表、编辑页标题与队列。 | 中性/琥珀 → 成功绿。 |
| 视频准备度 | 不可生成 / 缺少关键帧 / 可生成 | 工作室主工作区和批量工具栏。 | 阻断红、警告琥珀、可执行绿。 |
| 运行任务 | 排队 / 运行中 / 成功 / 失败 / 已取消 | 任务中心、镜头局部状态。 | 进度、时间与任务类型，避免覆盖确认状态。 |

禁止将“生成中”展示成 `shot.status`，也禁止用“已确认”暗示视频一定可生成。

### 5.2 加载、空和错误态

| 场景 | 规范 |
| --- | --- |
| 首次加载 | 使用与最终布局相近的 Skeleton 或局部 Spin，不能白屏。 |
| 刷新数据 | 保留已有内容并在局部显示刷新状态，避免整页跳动。 |
| 空列表 | 说明为空的原因，提供一个明确的创建/导入/返回动作。 |
| 表单校验 | 错误显示在控件附近，并将汇总错误通过 `aria-live` 或 `role="alert"` 宣告。 |
| API 失败 | 显示可读原因、重试动作和安全回退入口；toast 只能作为补充。 |
| 任务失败 | 在任务中心显示摘要，在业务页显示可修复项和“查看详情/重试”。 |

## 6. 关键页面规格

### 6.1 项目大厅与项目工作台

**目标**：让用户在一个屏幕内判断项目进度和下一步，而不是阅读所有统计。

- 项目卡展示：项目名、封面/视觉风格、最近更新时间、章节进度、唯一主 CTA。
- 项目工作台顶部保留项目定位、章节选择和动态“下一步”。
- 章节列表以阶段（原文、提取、准备、工作室）和阻塞原因组织，不以技术任务名作为主标题。
- 资产和文件 tab 显示关联数量、缺失警告和直达操作。

### 6.2 分镜编辑页（准备）

**目标**：高效处理候选并推进镜头确认。

```text
左：镜头队列（待确认优先）
中：基础信息 / 资产确认 / 对白确认
右或顶部：准备清单、完成度、进入工作室 CTA
```

- 镜头队列显示确认状态、候选待处理数和批量选择，但不展示运行时任务细节。
- 候选卡必须显示来源、建议关联、当前决定和可撤销动作。
- 所有候选处理完后，准备清单解释 `ready` 的原因，并提供“进入工作室”主 CTA。
- 允许维护性快捷入口，但不得让工作室替代确认操作。

### 6.3 分镜工作室（生成）

**目标**：将“能否生成”和“如何生成”集中到同一工作台。

```text
左：镜头选择、筛选和批量操作
中：帧图/视频预览与生成结果
右：准备度诊断、参数、模型与提交操作
```

- 默认优先展示被选中镜头的 video-readiness；阻断项按修复优先级排序。
- 缺少准备信息时，诊断应链接到编辑页中的具体镜头/区块。
- 参数变更、草稿预览和提交 payload 必须可解释，提交前显示供应商/模型能力限制。
- 多选批量生成前先展示可执行数量、被阻断镜头和原因。
- 拖拽分栏需要鼠标、键盘替代操作和最小/最大宽度；面板开闭状态持久化。

### 6.4 资产与模型管理

- 资产列表支持搜索、类型筛选、关联项目/镜头的上下文入口和清晰空状态。
- 资产详情区分“基础资料、参考图、生成任务、使用位置”，而不是将所有字段平铺。
- 模型页用能力矩阵表达支持的比例、时长、参考模式、seed/watermark，不将供应商原始字段暴露为默认表单。

### 6.5 任务中心

- 浮层默认展示当前上下文相关的活跃任务，再展示其他任务。
- 每项仅包含类型、状态、进度、耗时、取消与回跳；详情跳转到原业务页。
- 失败项必须提供“查看原因”和“回到原位置”，而不是让用户从任务中心排查所有输入。

## 7. 响应式与可访问性

| 断点 | 规则 |
| --- | --- |
| 375px | 管理列表单列；隐藏次要面包屑；不承诺完整工作室编辑能力。 |
| 768px | 项目与资产使用双列；表单双列可降为单列。 |
| 1024px | 分镜编辑页可使用双栏，工作室可以开启 inspector。 |
| 1440px+ | 工作室三栏布局，最大化预览与批量操作效率。 |

- 所有表单控件都有可见 label，不以 placeholder 作为唯一标签。
- 颜色不能是状态的唯一信号；Tag 必须包含文字，必要时配合图标。
- 焦点可见、Tab 顺序合理、弹窗可 Esc 关闭并正确返回焦点。
- 重要错误用 `role="alert"` 或 `aria-live`；长任务进度采用可读文本。
- 对比度至少达到 WCAG AA（普通文本 4.5:1）。

## 8. 改造优先级与验收

### P0：一致性与可理解性

- 收敛主色和状态 Tag 语义。
- 在所有主流程页区分确认、准备度、运行任务。
- 为页面级 API 失败增加原因、重试和回退。
- 补齐不可发现路由的导航决策。

### P1：核心生产效率

- 候选确认批量操作、可撤销与待处理排序。
- 工作室诊断清单与精确回跳。
- 任务失败的上下文内恢复。
- 统一 Empty / Skeleton / Error Boundary 模式。

### P2：可访问性与窄屏

- 建立键盘和屏幕阅读器验收清单。
- 为工作室提供窄屏只读/单栏降级。
- 完成国际化文案收敛，避免业务区硬编码语言混用。

**页面验收清单**：

- 用户可在 5 秒内找到主 CTA 与当前阶段。
- 任何阻断状态都能解释原因并给出下一步。
- 加载、空、失败、禁用和成功状态均可见且不只依赖颜色。
- 375px、768px、1024px、1440px 下无意外横向滚动；工作室窄屏按降级规则工作。
- 键盘可到达所有主操作，焦点和错误信息可感知。
